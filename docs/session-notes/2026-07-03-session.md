## 1. Dual-major (Umbraco 17 / 18) support — groundwork

**Goal:** support Umbraco 17 and the 18 RC (`18.0.0-rc1`) from one codebase.

**Key findings**
- Both majors run on `net10.0`, so TFM-based multi-targeting doesn't apply.
- Umbraco 18 **removed Swashbuckle** for OpenAPI (→ `Microsoft.AspNetCore.OpenApi`). The v17
  composer's types are gone in 18: `SwaggerGenOptions.SwaggerDoc`, `OpenApiInfo`,
  `BackOfficeSecurityRequirementsOperationFilterBase`, `IOperationIdHandler`/`OperationIdHandler`.
- **`Umbraco.AI` (a hard dependency) has no Umbraco 18 release.** Latest `1.14.0` pins
  `Umbraco.Cms.Core` to `[17.4.0, 17.999.999)`. The package *project* still compiles in v18 mode
  (direct `Umbraco.Cms.*` refs out-rank Umbraco.AI's constraint as an `NU1608` warning), but a real
  v18 consumer site (and `TestSite.v18`) fails to restore with a hard `NU1107` conflict. **So the
  18.x package cannot be published until a v18-compatible `Umbraco.AI` ships.**

**Decisions:** do the groundwork now; ship **version-aligned under one PackageId** (package major
tracks Umbraco major: 17.x → `[17,18)`, 18.x → `[18,19)`).

**Changes**
- `Umbraco.Community.AI.LogAnalyser.csproj`: added `UmbracoMajor` MSBuild switch (default `17`;
  `-p:UmbracoMajor=18` selects v18 refs + defines `UMBRACO_18`), conditional `Umbraco.Cms.*`
  version ranges, and a prominent comment about the Umbraco.AI blocker.
- `Composers/AILogAnalyserApiComposer.cs`: shared DI stays common; OpenAPI registration split behind
  `#if UMBRACO_18`. v18 path uses
  `builder.AddBackOfficeOpenApiDocument(name, doc => doc.WithTitle(...).WithBackOfficeAuthentication().ConfigureOpenApiOptions(o => o.AddOperationTransformer(...)))`.
  Exact namespaces confirmed from `18.0.0-rc1` assembly metadata:
  `AddBackOfficeOpenApiDocument`/`WithTitle`/`ConfigureOpenApiOptions` → `Umbraco.Cms.Api.Common.OpenApi`;
  `WithBackOfficeAuthentication` → `Umbraco.Cms.Api.Management.OpenApi`.
- Test sites: `TestSite.v18` → `Umbraco.Cms 18.0.0-rc1` + `UmbracoMajor=18` on the package
  ProjectReference; `TestSite.v17` pinned `UmbracoMajor=17`. Solution updated to include package +
  tests + `TestSite.v17` (the old single `TestSite` was deleted; `TestSite.v18` is left out of the
  solution until Umbraco.AI v18 ships, since it can't restore).
- `.github/workflows/release.yml`: derives `UmbracoMajor` from the tag's leading major and accepts
  prerelease tags (`18.0.0-rc1`).
- New `docs/BUILDING.md`: full dual-major strategy + the 4 steps to finish v18 once Umbraco.AI ships.

## 2. Fix: v17 test site `FileNotFoundException` after rename

**Symptom:** `Could not load file or assembly 'Umbraco.Community.AI.LogAnalyser.TestSite'` from
`FindAssembliesWithReferencesTo.ResolveAssemblies()` at startup.

**Cause:** renaming the assembly left the **old-named `bin` output** alongside the new one; Umbraco's
`TypeFinder` scans every assembly in `bin`, hit the orphan, and couldn't load it (not in the new
`.deps.json`).

**Fix:** stopped the running `iisexpress` (it was holding file locks), deleted `bin`/`obj`, rebuilt.
Output now contains only `...TestSite.v17.*`. Lesson: after any project/assembly rename, delete
`bin`/`obj` once — `dotnet clean`/incremental builds don't purge differently-named artifacts.

## 3. Easter egg: "snarky mode" (Marvin the Paranoid Android)

A hidden, off-by-default mode that makes the AI respond in-character.

- `Models/AILogAnalyserSettings.cs` (new): bound from the `AILogAnalyser` section; `bool SnarkyMode`
  (default `false`). Registered in the composer.
- `Controllers/AILogAnalyserApiController.cs`: when snarky is on, appends a persona instruction to the
  **system** prompt — deeply snarky/cheeky/bone-dry/condescending in the voice of **Marvin the
  Paranoid Android** ("brain the size of a planet", terminally depressed). After iteration, the final
  wording explicitly says it does **not** need to provide genuinely helpful advice or accurate
  diagnosis — pure miserable entertainment (headings may be vague/evasive/defeatist).
- **Enable it (dev only):** `AILogAnalyser: { "SnarkyMode": true }` in `appsettings`. (It was toggled
  on in `TestSite.v17/appsettings.Development.json` during the session; current committed state is
  controlled by that file.)
- Deliberately **undocumented** in README/CLAUDE/BUILDING/marketplace — only code + test names.

## 4. Snarky UI: warning banner + "Re-analyse without snark"

Backend + frontend so the UI reflects snark and can opt out per-request.

- `Models/LogAnalyserRequest.cs`: added `bool? Snarky` (per-request override; null → use config).
- `Models/LogAnalyserResponse.cs`: added `bool Snarky` (what was actually used).
- Controller: `snarky = request.Snarky ?? _settings.SnarkyMode`; returned on the response.
- `Client/src/log-ai-summary-dialog.element.ts`: `_snarky` state from the response; an amber
  **warning banner** at the top of the modal when snarky; a **"Re-analyse without snark"** action
  (shown only when the current result is snarky) that re-runs with `snarky: false`; the normal
  "Re-analyse" still respects the configured default. Rebuilt the client (`npm run build`).

## 5. Prompt token-efficiency pass

Reviewed the full generated prompt; the system-context **assembly inventory** was the dominant,
lowest-value cost (~183 lines ≈ 1,500–2,200 tokens/request of transitive deps).

Implemented (all in `Services/SystemDiagnosticsProvider.cs` unless noted):
1. **Assembly allowlist** instead of a framework denylist: keep anything containing "umbraco"
   (case-insensitive), the application's own entry assembly, and a curated `RelevantAssemblyPrefixes`
   set of commonly-implicated infrastructure (`uSync`, `Examine`, `NPoco`, `Microsoft.Data.`,
   `MailKit`/`MimeKit`, `SixLabors`, `Smidge`, `StackExchange.Redis`, `Hangfire`, `Newtonsoft.Json`).
   `Serilog.*` and `Lucene.Net.*` deliberately left out (high line-count / low marginal value).
2. **Collapse same-version sub-assemblies** by package family (first 3 name segments) →
   `Umbraco.AI.Agent.* 1.10.4 (9 assemblies)`; single-assembly families print in full. Kept provider
   names like `Umbraco.AI.OpenAI`.
   - Net: ~183 → ~40 lines. Safety net: anything excluded still appears in the exception **stack
     trace** when it throws.
3. **`Properties` truncation** lowered 8 KB → **2 KB** (`MaxPropertiesLength`) in the controller;
   Message/Exception/Template stay at 8 KB.
4. **Prompt-caching restructure** (controller): all static content (instructions + diagnostics) now a
   single `ChatRole.System` **stable prefix**; only variable log data in the `ChatRole.User` message;
   snarky addendum appended **last** so it never splits the cacheable prefix. Enables OpenAI automatic
   prefix caching / Anthropic explicit caching → lower cost + faster TTFT. Perf log now reports
   `systemPrompt.Length + userPrompt.Length`.
